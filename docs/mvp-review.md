# Проверка MVP v0.1

## Запуск демонстрации

1. Поднять PostgreSQL, применить миграции и запустить API по [инструкции бэкенда](../backend/README.md).
2. Запустить [фронтенд](../frontend/README.md). Для админского сценария создать отдельного администратора командой `python -m scripts.create_admin <username>`.
3. Зарегистрировать пользователя. Добавить доход и расход и сверить итог за текущий месяц. Открыть фильтр по типу или категории, затем изменить и удалить операцию.
4. Войти администратором, сбросить пароль тестового пользователя и проверить вход с новым паролем.

## Результат проверки 14.11.2026

- PostgreSQL 16, чистая БД, миграции Alembic применены.
- Pytest проверил регистрацию и откат при сбое создания категорий, выдачу JWT, форму Swagger Authorize, сброс пароля, права администратора, фильтрацию, пагинацию, суммы, изоляцию и редактирование операций.
- В Edge на ширине 390 px проверены регистрация, сохранение сессии после перезагрузки, добавление, редактирование и удаление операции, фильтр по типу, отрицательный баланс, сброс пароля и вход с новым паролем. У обычного пользователя административный пункт меню скрыт.
- Обнаруженные ранее дефекты Swagger Authorize и проверки пароля в `create_admin` исправлены и перепроверены. Перед демонстрацией повторить сценарии на ветке, которую будет принимать команда.

## Материалы к приёмке и ретроспективе

Готовый сценарий демонстрации охватывает регистрацию, вход, операции, итоги и администрирование. Совместное решение о приёмке v0.1 следует зафиксировать в #23 с указанием проверенной версии.

На ретроспективе стоит разобрать две причины задержки: одинаковые головы веток регистрации и входа и отсутствие сквозной проверки до ревью. Для следующего этапа сверять разницу между соседними PR и запускать API-тесты и браузерные сценарии перед передачей на приёмку.
